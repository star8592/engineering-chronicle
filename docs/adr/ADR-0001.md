# ADR-0001：Engineering Chronicle V0.1 架构收敛与实施基线

日期：2026-10-09（Asia/Shanghai）  
状态：主代理提出的实施基线；允许在后续实现验证中以新 ADR 修订。  
输入：GENESIS-0000 v1.0-draft；GENESIS-REVIEW-0001（GPT-6.1 Sol 独立评审）。  
性质：对评审的逐项回应与工程方案，不是产品完成记录，也不是双模型共同批准。  
历史规则：不修改原创世档案或独立评审；本文件作为新的决策记录追加。

## 1. 本轮结论

保留 Chronicle / Universe / Intelligence 的长期愿景，以及六对象作为领域语言。V0.1 围绕来源陈述、平台接收、独立验证建立一个可运行的纵向闭环。三大内核是能力边界，不要求三个进程或三个服务。

V0.1 完成的含义：一个真实 Rust 项目出现失败，修复后复测；记录两次结果及其精确版本，导出证据包，在主服务停止且断网时按外部信任政策核验。篡改、回滚、缺证据与陈旧报告必须分别得到可解释的拒绝或未知结果。

## 2. 对八项异议的处理

| 异议 | 处理 | 理由与实施影响 |
|---|---|---|
| REV-01 六对象混合不同层次 | 采纳协议分层，保留六对象 | Event/Evidence 等表达业务含义；Statement/Receipt/Assessment 表达信任边界，二者并不冲突。 |
| REV-02 外部固定检查点 | 纳入 V0.1 | 核验输入必须包含由核验者先前持有或从可信渠道取得的头；包内自带头不能独自证明没有回滚。 |
| REV-03 日志完整性与现实覆盖 | 采纳 | 独立报告账本前缀完整性、登记来源覆盖、已知缺口；不声称覆盖从未登记或无法观察的操作。 |
| REV-04 来源与平台签名分离 | 采纳 | 来源签署其确定字节；平台另行分配叶索引和接收时间，避免签名自引用与冒充来源确认。 |
| REV-05 VERIFIED 不能自设 | 采纳 | 验证结论为追加记录，绑定主体摘要、规则、环境、证据与适用条件；源数据声称的状态不能直接升级为门禁结果。 |
| REV-06 关联与因果区分 | 采纳 | 首版只保存带类型、来源和依据的关系；统计因果推断延后。 |
| REV-07 首版 crate 过多 | 采纳四 crate 基线 | 减少过早的接口拆分；数据库适配在 CLI 内部模块实现，后续有独立复用需求再拆。 |
| REV-08 重建与执行重演区分 | 采纳分期 | V0.1 重建读取事件并运行纯投影，不执行历史工具命令；未来实验运行器另设协议与验收。 |

这是主代理的回应，未发生第二轮 GPT-6.1 反驳或第三方裁决。独立评审者有权在后续指出本文件的新缺陷。

## 3. 最小模型

| 对象 | 权威内容 | 不能代表的保证 |
|---|---|---|
| Statement | 来源身份、命名空间、来源 epoch/sequence、声称时间、动作、subject/evidence 摘要、带类型关系 | 陈述真实、测试充分、已入账 |
| Receipt | 日志身份、epoch、连续叶索引、Statement envelope 摘要、平台观察时间、授权政策摘要 | 来源同意平台排序、历史已外部固定 |
| Assessment | 被评估对象摘要、规则和环境摘要、执行器、证据、结果及适用范围 | 对象永久正确、未覆盖性质通过 |
| Checkpoint | 日志身份、epoch、tree_size、root、算法配置、签名 | 全网最新、现实无遗漏、内容安全 |
| Coverage | 登记来源、采集范围、游标/窗口、核对方式、已知缺口 | 未登记活动的完整历史 |

State 是指定检查点与 projector 版本下的派生结果；Invariant 是版本化规则；Experiment 是隔离命名空间中的新活动。Evidence 是资产及来源描述，不必成为独立部署服务。

## 4. V0.1 必须冻结的协议规则

1. 明确每种记录的 payload type、schema 版本、字段约束和拒绝条件。未知可选扩展可以保留；未知影响验证的关键字段必须拒绝。
2. 采用受限 JCS JSON 作为候选编码，SHA-256 与 Ed25519/DSSE 作为候选密码学配置；通过官方向量及跨实现负例后才冻结实现。不能把普通 JSON 序列化称为 JCS。
3. 不接受浮点计数器；计数器使用无符号规范十进制字符串，禁止前导零（零本身除外），限制最大范围。摘要、时间格式、Unicode 字节、对象大小及深度都有上限。
4. 稳定业务 ID、内容摘要、签名 envelope 摘要分别定义；签名不覆盖自身。Receipt 对应的平台签名 envelope 作为叶输入时，要明确精确字节和域分离，不能把 receipt_signature_ref 递归放进待签内容。
5. 同一 project/source/epoch/sequence 与相同摘要重投返回同一 Receipt；不同摘要为冲突。来源 epoch 变更需授权登记，不能靠换 epoch 绕过去重或掩盖缺口。
6. 平台持久化确认、检查点生成、外部固定是不同状态。返回成功必须说明已经达到哪一级。
7. 信任根来自核验者外部配置；keyid 与包内公钥只是定位信息，不能自行授予权限。权限绑定命名空间和动作类型。
8. 检查点没有可信时间来源时，仅证明签署内容与前缀，不证明真实发生时间。最新性以外部头和约定窗口分别评估。
9. 轮换、撤销、失陷时间与历史授权政策分开记录。未来新密钥不得重新签署并替换旧历史。
10. 源记录及证据包含敏感内容时，先定义最小不可变字段与可删除资产；不默认永久采集完整工具输入、凭证或用户原始数据。

本文件不声称这些候选选择已通过实现向量，也不宣称兼容完整 SCITT/SLSA 协议。供应链适配后续使用已有标准材料，避免发明同名兼容性。

## 5. 入账与恢复边界

PostgreSQL 是权威追加数据存储；证据 CAS 是独立资产存储；投影是可删除重建的读模型。

| 操作 | V0.1 策略 |
|---|---|
| 连续叶索引 | 按日志流锁定事务计数器；与账本行同事务提交，不用 sequence 缺号判断遗漏。 |
| 资产写入 | 先完成内容校验与持久化，再记录 available；失败或缺失显式保留为未完成/不可用。 |
| 后到证据 | 追加 availability/association 陈述；不修改既有叶字节。 |
| 回执与通知 | 账本和 outbox 同事务；ACK 丢失可幂等重试，通知失败不撤销入账。 |
| 检查点 | 从已提交前缀生成；签署任务幂等，并持久保存签署结果，避免同一根反复制造不同 envelope。 |
| 备份恢复 | 与外部固定头比较；落后时停止对外声称正常与继续签头，先恢复记录或明确进入新恢复 epoch。 |
| 投影恢复 | 从指定前缀和规则版本重建；摘要差异作为新问题记录，不能改账本使之匹配。 |
| CAS 孤儿清理 | 有宽限期；以引用核对与并发保护避免删除尚在提交的资产。 |

首版只保证单项目单顺序流。多来源可以向该流提交；不由此宣称跨项目总序或分布式共识。容量测试不足时先记录限制，再决定是否分片。

## 6. Rust 工程结构

| crate | 责任 |
|---|---|
| chronicle-protocol | 类型、限制、规范字节、错误分类、标准/负例 fixtures |
| chronicle-core | 追加语义、去重、Merkle 与检查点、确定性投影 |
| chronicle-cli | 入账、查询、导出；PostgreSQL、CAS 与第一个 CI 适配模块 |
| chronicle-verifier | 离线读取有限格式证据包并输出分项核验；无 DB、联网和历史执行接口 |

离线 verifier 不链接服务、数据库或执行器模块。允许复用协议代码，但清楚标记共同缺陷风险。编码与证明至少使用外部标准向量；测试生成器不能只调用被测实现得到期望结果。第二实现交叉检查在高保证阶段引入。

| EC-005 版本化投影与覆盖 | 时点查询、后到事件、来源核对 | M10/M11/M12；恢复同版本摘要，已知缺口可查询 |

M01–M14 的完整输入和预期结果保持引用 GENESIS-REVIEW-0001 §8；实施时逐项建立执行记录。每条执行证据包括 commit、命令、工具/规则版本、环境、原始结果及摘要。

首版结果按 BYTE_INTEGRITY、SIGNATURE、AUTHORIZATION、PREFIX_CONSISTENCY、EVIDENCE_AVAILABILITY、POLICY_RESULT、COVERAGE、FRESHNESS 分项输出。通过完整性检查不自动通过发布政策；未知/陈旧/缺证据必须保留。
