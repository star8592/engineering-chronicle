# ADR-0003：实验性 header 封套与待签字节边界

日期：2026-10-09（Asia/Shanghai）  
状态：实验性实施决策；完整 Statement 封套与信任政策尚未冻结。  
承接 ADR-0001，不改写历史档案。

## 决策

为现有 `ec.statement-header.v0.1` 草案建立 `HeaderEnvelopeCandidate`。它仅表示封套格式和header输入合格，没有已验证签名、身份或授权状态。完整Statement需要另行定义声称时间、证据、关系和业务载荷，并使用新的payload type；不得把本header类型冒充完整Statement。

采用DSSE v1 PAE编码：将payload type与原始payload的UTF-8/二进制字节长度及内容绑定。类型固定为 `application/vnd.engineering-chronicle.statement-header.v0.1+json`，仅为项目自定义实验类型，不表示已在IANA注册。签名候选不参与自身待签字节。

输入载荷必须已经等于受限JSON规范字节。非规范输入即使JSON含义相同也拒绝，绝不以重新编码的字节替代收到的载荷再验签。不可变candidate保留这一唯一字节来源，应用读取和未来验签使用同一份内容。

外部JSON受1 MiB/32层限制；签名候选1–8个，每项必须解码为64字节，以匹配候选Ed25519配置。此检查不验证曲线、签名、密钥、门限或真实性；重复签名候选也不形成已验证人数。标准/URL-safe Base64与有/无padding均接受；拒绝非法字符、非零尾部填充bit及混合字母表。

keyid缺失或空字符串等价为无提示，非空使用受限Identifier。keyid属于未认证定位提示，不能成为principal、source所有权或授权决定的依据。实际可信公钥及project/source/epoch/kind范围应来自独立外部政策；以后仅对不同可信公钥的成功验签计数。

## 与通用DSSE的差异

本实现使用DSSE签名框架和PAE编码，但属于更严格的Chronicle实验配置，不声称为完整通用DSSE消费者：拒绝未知外层/签名字段、限定payload type、强制规范JSON、限定Ed25519候选字节长度/签名数量/keyid语法。DSSE推荐JSON envelope要求忽略未知字段，允许其他算法与任意载荷字节；本配置明确没有这些兼容保证。

Base64文字表示与外层排版可以不同，待签字节相同。本步尚未定义最终平台Receipt所引用的envelope摘要、规范导出规则或内容ID，不能把待签字节当成envelope摘要，也不能将subject字段视为已计算资产摘要。

## 实测与后续门槛

36项Rust测试包含官方HelloWorld PAE向量、UTF-8字节长度、二进制载荷、Base64变体、重复键、非规范载荷、未知字段、签名数量和长度负例。Python CLI检查另行构造PAE，不调用Rust函数生成期望值。以上仅证实编码和解析边界，不证实密码学或产品验收。
